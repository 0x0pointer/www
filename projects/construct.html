Construct

Construct scans every pull request in your GitHub org for security bugs. A GitHub App sends PR events to one central service, which runs a short chain of agents on the change: triage, hypothesise, static verify, skeptic, dynamic. Bugs that survive are replayed against the PR’s own app, so a finding arrives already proven. Dev teams change nothing in their CI.

What it does

A scanner that has to prove it.

Nothing to install per repo

One GitHub App, read-only permissions, one central service. Every PR in the org is scanned on open and on push. Findings come out as SARIF and on an AppSec dashboard; nothing is written back to the PR.

Citations checked by code

Every file:line and quote an agent cites is matched against the real source after the stage ends. A citation that does not match drops the hypothesis, so a hallucinated location never reaches you.

Agent-free replay

The agent writes a declarative PoC. Code then replays it in fresh environments, twice on the PR and once on the base branch, with fresh canaries each time. An oracle never passes on a value the PoC itself sent.

Isolated by construction

Each agent runs in its own container on a per-scan internal network. The running app can reach mock services and a DNS sink that records everything else. Only a small launcher service holds the Docker socket.

Sandbox

Three hypotheses, three labels.

A finding gets exactly one label, and the label says how much proof stands behind it. Pick a hypothesis to see where it ends up and why.

One policy file

Any harness, any model, per stage.

AppSec owns a central policy.yaml that picks the agent harness, model, time limit, and dollar budget for each stage; repos cannot override it from a branch. Harnesses only ever see model aliases and a short-lived key minted per task, and the judge runs on a different model family from the agent it reviews to reduce correlated mistakes. The methodology itself is nine harness-neutral skills, measured against a labelled eval corpus on every change.

In the loop

The intelligence half of the loop.

Today

Construct reads each change, forms hypotheses about impact and abuse cases, verifies them against the code, and proves the survivors in an ephemeral environment built from the PR branch.

Next

Its hypotheses, new routes, and trust-boundary changes flow into Source, where Agent-Smith retrieves them as prioritized targets for runtime testing against staging.

Quickstart

Run the tests, then scan a PR.

terminal
$ git clone git@github.com:0x0pointer/Construct.git && cd Construct
$ python3.12 -m venv .venv && .venv/bin/pip install -e '.[dev]'
$ make test && make test-e2e # the full pipeline, with a scripted agent
 
$ cp .env.example .env && make images && make up # the whole org, on one VM
 
✓ open a PR and follow the scan with prsec-trace <scan id> --follow

Three paths: run the tests, scan a real PR from your laptop, or deploy for the whole org.
